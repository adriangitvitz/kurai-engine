# Using Kurai with AI Agents

Kurai exposes its search + content extraction pipeline as a [Model Context
Protocol](https://modelcontextprotocol.io/) server. Any MCP-compatible
agent - Claude Code, Cursor, custom MCP clients - can call its 5 tools
directly. This guide covers setup, the tool surface, and patterns that work
well in practice.

## Quick setup

Start the stack as described in the [README](../README.md#quick-start), then
register the MCP endpoint with your client. With Claude Code:

```bash
claude mcp add --scope user --transport http kurai http://localhost:8080/mcp
```

Verify with `claude mcp list`. `kurai` should show as connected with 5 tools.

Authentication is off by default. If Kurai is reachable by anyone other than
you, turn it on first.

## Setup with authentication

### 1. Create an API key for the agent

```bash
docker compose exec kurai /app/kurai gen-key --user alice --name "Alice"
```

The output is split between two streams:

- **stdout**: the raw API key, one line. This is the value for
  `Authorization: Bearer <key>`. Save it now. Kurai stores only its hash, so
  it cannot be recovered.
- **stderr**: a ready-to-paste `users.yaml` entry.

Paste the entry into `users.yaml`:

```yaml
users:
- id: alice
  name: "Alice"
  key_hash: <hash printed by gen-key>
  enabled: true
```

Repeat for each user. To revoke a key, set `enabled: false` and run
`make redeploy`.

### 2. Turn authentication on

Set `KURAI_AUTH_ENABLED=true` in `.env`. The signing secret
`KURAI_AUTH_SECRET` was already generated by `make setup`.

```bash
make redeploy
```

Confirm:

```bash
curl "http://localhost:8080/health"
curl "http://localhost:8080/search?q=test"
curl -H "Authorization: Bearer <raw-key>" "http://localhost:8080/search?q=test"
```

The first call returns the status, the second returns `401`, and the third
returns results.

### 3. Connect the agent

Over HTTP:

```bash
claude mcp add --transport http kurai http://localhost:8080/mcp \
  --header "Authorization: Bearer <raw-key>"
```

Use `localhost` for command-line clients. Container hostnames such as
OrbStack's `*.orb.local` are not resolved by every CLI.

Over stdio, for a binary installed on the host rather than in a container:

```bash
go install github.com/adriangitvitz/kurai/cmd/kurai@latest
claude mcp add --transport stdio kurai -- "$(which kurai)" mcp \
  -config "$HOME/.config/kurai/config.yaml"
```

Stdio mode does not use Bearer authentication, because the process runs as
the user who owns the binary.

## What the server tells your client

On `initialize`, kurai sends `instructions` - routing, the token knobs, and the
error policy - which most clients paste into the model's system prompt. All
five tools are annotated `readOnlyHint` / `idempotentHint` / `openWorldHint`,
so a client can auto-approve them and retry a call that failed in transit.

The transport pings connected clients every 30s (`mcp.keepalive`) and closes
sessions idle for 30m (`mcp.session_timeout`). The ping exists because the
notification stream is otherwise silent and clients tear down a silent
transport.

## The 5 tools

| Tool | When to use |
|---|---|
| `web_search` | Research, fact-finding, docs lookup. Returns ranked URLs + snippets. |
| `news_search` | Time-sensitive queries: "what happened this week", current events, recent product launches. Has clustering to deduplicate wire-syndicated stories. |
| `image_search` | "Find me a diagram of X", reference images, product photos. Returns image URLs with width/height/format. |
| `extract_content` | Read a specific URL in full. Returns clean markdown stripped of nav/ads/footer. Use after `web_search` to dig into the most promising result. |
| `find_similar` | Given a URL, find related articles. Internally extracts the URL's title, derives a search query, excludes the source host. The "more like this" navigator. |

### Tool input schemas

Every tool accepts a `query` (or `url`) plus optional knobs. Full schemas
are in [`internal/mcp/tools.go`](../internal/mcp/tools.go) but the most
useful flags:

```jsonc
// web_search
{
  "query": "required, non-empty",
  "limit": 10,                         // 1-20
  "category": "tech|academic|news|sports|general",  // override auto-detection
  "include_domains": ["arxiv.org"],    // post-filter
  "exclude_domains": ["reddit.com"],   // post-filter
  "language": "en",                    // BCP-47
  "date_from": "2024-01-01",           // YYYY-MM-DD
  "date_to":   "2024-12-31",
  "snippet_length": 200,               // truncate snippets to N chars
  "response_format": "compact",        // compact (MCP default) | full (adds debug fields)
  "extract_top": 3,                    // fused search+extract: top-N pages' markdown attached as 'content' (1-5)
  "max_chars": 32000                   // total body budget for this response, split across extracted pages; 0 = no limit
}

// extract_content
{
  "url": "required",
  "format": "markdown|text|both",      // default markdown
  "include_images": false,
  "include_links": false,
  "timeout_ms": 10000,                 // 1000-30000
  "focus": "refresh token rotation",   // rank heading-chunks against this query, best first
  "passages_only": true,               // with focus: omit full content - max token saving
  "top_passages": 5,                   // with focus: how many passages (default 5)
  "max_chars": 32000                   // cap the returned body; 0 = no limit
}

// find_similar
{
  "url": "required",
  "limit": 10                          // 1-20
}
```

### Token-efficiency knobs (use these by default)

Four parameters exist specifically to cut agent token spend; measured on
live responses:

1. **`response_format=compact`** - strips per-result debug metadata
   (badges, signal_ranks, domain_scores, redundant scores): **~60% fewer
   tokens** on a 10-result response. Already the default over MCP; pass
   `full` only when you need to debug why something ranked where it did.
2. **`extract_top=N`** - fuses search+extract: one round trip and one LLM
   turn instead of two. Use when you know you'll read the top hits (most
   research loops). Failures degrade gracefully - a result whose page can't
   be extracted just ships without `content`. The extraction wave is bounded
   by a global budget (default 8s), so one slow CDN can't stall the response;
   a result missing `content` may simply have been too slow - call
   `extract_content` directly if you specifically need it.
3. **`focus=` + `passages_only=true`** - for long pages, returns only the
   heading-chunks relevant to your question instead of the full body. A
   4,000-word spec becomes ~200 tokens of the right section.
4. **`max_chars`** - page bodies are capped at **32,000 characters per call**
   by default (~8k tokens). On `web_search` the cap is a budget for the whole
   response, split across however many pages `extract_top` attached - so
   `extract_top=5` costs about the same as `extract_top=1`, not five times as
   much. A truncated body carries an inline marker saying how much was dropped.
   Pass `max_chars: 0` for no limit; prefer `focus` + `passages_only` instead.

Measured on live responses after these caps: `extract_content` on a long
Wikipedia article dropped from ~17,600 to ~8,300 tokens, and
`web_search extract_top=5` from ~14,000 to ~8,400.

## Response fields the agent should care about

### Search results - compact format (MCP default)

```jsonc
{
  "url": "...",
  "title": "...",
  "snippet": "...",
  "score": 0.0721,                     // post-RRF, post-MMR final score
  "final_rank": 3,                     // displayed position (post-MMR reordering)
  "rrf_rank": 1,                       // position after BM25/RRF fusion
  "engines": ["bing", "yahoo", "duckduckgo"],  // multi-engine = stronger corroboration
  "domain": "programming",             // doc's classified domain
  "published_date": "2025-11-25T00:00:00",     // omitted if unknown
  "content": "## Heading\n..."         // only when extract_top covered this result
}
```

### Instant answers (`answers` block, both formats)

Trigger-matching queries ("100 usd to mxn", "weather in oaxaca", entity
lookups) may carry a bounded `answers` block alongside the ranked results -
in `full`, `compact`, AND the MCP `web_search` result. When present it can
replace an entire search-then-extract round trip; when absent the response
gains zero bytes (the block is omitted, never empty scaffolding).

```jsonc
{
  "answers": {
    "currency":    { "base": "USD", "quote": "MXN", "amount": 100, "converted": 1742.51,
                     "rate": 17.4251, "rate_date": "2026-07-17", "source": "frankfurter",
                     "minor_units": 2 },
    "weather":     { "place": "Oaxaca City, Mexico", "timezone": "America/Mexico_City",
                     "temperature_c": 24.1, "condition": "Partly cloudy",
                     "forecast": [ /* ≤8 periods */ ],
                     "source": "open-meteo", "as_of": "2026-07-17T14:00:00Z" },
    "infobox":     { "title": "...", "summary": "...", "attributes": [ /* ≤8 */ ],
                     "links": [ /* ≤3 */ ], "source": "wikipedia" },
    "corrections": ["did-you-mean refinement"]      // ≤3
  }
}
```

Hard ceilings (token cost is falsifiable): weather = current + ≤8 forecast
periods; infobox summary ≤500 chars, ≤8 attributes, ≤3 links, ≤1 image;
≤3 corrections; **≤4096 bytes total** serialized answer content per
response. Every member carries a machine-readable `source` and an ISO 8601
as-of where time-sensitive (`rate_date`, `as_of`). At most one utility
answer (currency XOR weather) per response. Answer failures degrade
silently - absence is the routine path, never an error.

### Search results - full format (`response_format=full`)

Adds debugging metadata on top of the compact fields: `badges`
(reputable/content_farm/known_spam/authoritative), `signal_ranks` (per-signal
rank positions feeding RRF), `domain_scores` (classification distribution),
`rrf_score`, `intent_alignment`, `original_score`, `adjusted_score`. Use for
"why did this rank here?" investigations, not routine searches.

**`rrf_rank` vs `final_rank`** are the most useful agent signals: when they
differ, MMR moved the result for diversity. A doc with `rrf_rank=1` but
`final_rank=5` was demoted because it was too similar to a higher-ranked
result. If you specifically need that doc, page further or filter the candidate
set.

### Article extraction (`extract_content`)

```jsonc
{
  "url": "https://...",
  "final_url": "https://...",          // post-redirect
  "title": "...",
  "byline": "...",                     // nullable
  "published_date": "2025-11-25...",   // nullable
  "site_name": "...",                  // nullable
  "language": "en",
  "content_markdown": "## Heading\n\nBody...",
  "content_text": "...",               // populated when format=text|both
  "excerpt": "first ~240 chars...",
  "word_count": 1853,
  "fetched_at": "2026-04-30T...",
  "cache_hit": false                    // 24h cache
}
```

The markdown preserves heading hierarchy (`##`, `###`) - useful when the
agent needs to extract a specific section. Boilerplate (nav, footer, ads,
related-posts) is stripped via [trafilatura](https://github.com/markusmobius/go-trafilatura).

With `focus=<query>`, the response additionally carries ranked passages:

```jsonc
{
  "result": { /* article as above; content fields empty if passages_only */ },
  "passages": [
    { "heading": "Refresh Tokens", "text": "Authorization servers MAY...", "score": 4.21 },
    { "heading": "Token Expiry",   "text": "Access tokens SHOULD...",      "score": 1.87 }
  ]
}
```

Passages are heading-delimited chunks BM25-ranked against the focus query,
descending. The underlying article cache is focus-independent - asking the
same URL with different focus queries reuses the cached extraction.

### Errors

The HTTP API uses this envelope. Switch on `code`, not `message`:

```jsonc
{ "error": { "code": "missing_query", "message": "...", "details": {} },
  "request_id": "req_..." }
```

Over **MCP** the same information arrives as the tool result body, with
`isError: true` and a flat JSON object:

```jsonc
{ "code": "upstream_unavailable", "message": "...", "retryable": true,
  "status": 503, "request_id": "req_..." }
```

`retryable` is the field to branch on for retry-vs-give-up; it is true only for
`fetch_timeout` and `upstream_unavailable`. `request_id` is unique per tool
call, so quote it when reporting a failure.

Stable codes: see [docs/error-codes.md](error-codes.md). Most relevant for agents:

| Code | Meaning |
|---|---|
| `unauthorized` | Bad/missing Bearer token. Re-check `Authorization` header. |
| `rate_limited` | Too many failed auth attempts. Back off ≥60s. |
| `invalid_url` | `/extract` got a bad URL or a private/internal IP. |
| `unsupported_content_type` | `/extract` got a PDF/binary. Skip or use a different tool. |
| `extraction_failed` | Page fetched but trafilatura found no main content. Try another result. |
| `fetch_timeout` | Upstream took too long. Retry once. |
| `upstream_unavailable` | SearXNG returned an error or no usable response. Wait and retry. |

## Patterns that work

### Research → drill in → expand

```text
1. web_search("kubernetes pod stuck terminating finalizer", extract_top=3)
   # one call: ranked candidates AND the top-3 pages' full markdown
2. find_similar(top_result.url)               # broaden if needed
3. extract_content(other_url, focus="...")    # targeted deep-dive on a specific section
```

This is the canonical agent research loop, collapsed: `extract_top` fuses the
old search-then-extract round trips into one call, `find_similar` gives
breadth, and a focused `extract_content` digs into pages outside the top hits
without paying for their full body.

### Date-filtering for "what's new"

```jsonc
// Only news from this month
{ "name": "news_search", "arguments": { "query": "anthropic claude", "time_range": "month" } }

// Or for web_search with a precise window
{ "name": "web_search", "arguments": { "query": "react server components", "date_from": "2025-01-01", "date_to": "2025-12-31" } }
```

`time_range` is the news-specific shortcut (day/week/month/year). For web
search, use `date_from`/`date_to` - but be aware that not all results carry
a parseable `published_date`.

### Authoritative-source bias

```jsonc
// Only return results from a curated set
{
  "name": "web_search",
  "arguments": {
    "query": "cognitive behavioral therapy",
    "include_domains": ["apa.org", "nih.gov", "mayoclinic.org"]
  }
}
```

Useful for high-stakes queries (medical, legal, financial) where you want
to constrain to vetted sources.

### Pagination

```jsonc
{ "query": "...", "limit": 10 }    // page 1
// Response includes envelope.pagination.has_more + .next_page
```

Re-call with `page: N` to walk forward.

## Limitations + gotchas

1. **SearXNG nondeterminism**. The upstream meta-search depends on which
   engines respond per query (Google is permanently IP-blocked at our
   level; Yahoo/DuckDuckGo/Brave/Bing/Wiby/Presearch rotate by health).
   Same query 30s apart can give slightly different top-10. Treat
   `web_search` as approximate, not deterministic.

2. **MMR reorders for diversity**. The displayed `final_rank` order is not
   `final_score DESC`. Look at `rrf_rank` to see the pre-MMR ordering.

3. **Image dimensions are best-effort**. Most engines populate `resolution`
   and we parse it, but some don't - those images report `width=0
   height=0`. Filter or sort accordingly.

4. **News dates are spotty**. SearXNG often returns news without parseable
   dates. Undated results render with `published_date: null` (since the
   Go zero-time fix). Don't rely on the field always being present.

5. **`/extract` PDFs return 415**. Trafilatura is HTML-only. If you need
   PDF text, fetch the bytes yourself and run a separate extractor.

6. **Caching**. Web search caches per `(userID, query)` for 5 minutes.
   `/extract` caches for 24 hours. If you hit the cache, response includes
   `meta.from_cache: true` and `envelope.cached_at`.

7. **Out-of-range arguments are rejected, not clamped.** `limit=99`,
   `extract_top=20`, `timeout_ms=5` and friends return `invalid_request` with
   the valid bounds in the message. A silent clamp used to make a wrong
   argument look like a thin result set.

8. **`limit` sets the page size.** It is pushed into the service, so
   `meta.page_size` and the pagination cursor agree with what you asked for,
   and `extract_top` only fetches pages you will actually receive.

9. **No rate limiting on search/extract**. Only `/auth` is rate-limited
   (per-IP). A misbehaving agent could hit upstream SearXNG hard. Add
   reasonable inter-call sleeps if you're issuing many queries fast.

## Self-hosted reranker (optional)

For tasks that benefit from a second-pass cross-encoder rerank, enable the
TEI sidecar:

```bash
docker compose --profile reranker up -d
```

Then in `config.yaml`:

```yaml
reranker:
  enabled: true
  provider: tei
  url: http://tei:80
  blend_alpha: 0.6     # 0=pure RRF, 1=pure CE
  top_n: 30
```

First boot pulls `BAAI/bge-reranker-v2-m3` (~600 MB). Live verify with the
golden eval (`go test ./internal/ranker/ -run TestGolden_NDCGFloor -v`)
that the lift is worth the latency before defaulting it on.

## Checking your setup

```bash
# Smoke-test the MCP transport without an agent
SESSION=$(curl -sD /tmp/h \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -X POST --data '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"smoke","version":"1"}}}' \
  http://localhost:8080/mcp >/dev/null
  grep -i 'mcp-session-id' /tmp/h | awk '{print $2}' | tr -d '\r')

curl -s -H "Authorization: Bearer $KEY" -H "Mcp-Session-Id: $SESSION" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -X POST --data '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  http://localhost:8080/mcp >/dev/null

curl -s -H "Authorization: Bearer $KEY" -H "Mcp-Session-Id: $SESSION" \
  -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -X POST --data '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' \
  http://localhost:8080/mcp \
  | grep '^data: ' | sed 's/^data: //' | jq '.result.tools | map(.name)'
# → ["web_search","news_search","image_search","extract_content","find_similar"]
```

If that returns the 5 tools, your stack is ready.
